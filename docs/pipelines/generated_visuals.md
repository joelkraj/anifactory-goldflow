# Generated-Visuals Operating Contract

This lane continues to exclude legacy render paths, old visual heuristics, source-seed annotations, regex SFX production fallback, and legacy multi-route compatibility behavior from the original AniFactory repo.

Required for `media_workflow: generated_visuals_v1`, including legacy episode identities that have no `media_workflow` field. Read this complete technical guide and the selected content-family guide before production actions. The detailed [video production workflow](../workflows/video_production_workflow.md) expands the same stage chain.

Content profile and media workflow are different axes. This document defines generated-image/reference/motion artifacts, narration, validation, approvals, provider locks, recovery, and rendering. It does not select a fiction genre, protagonist, source-writing template, illustration style, title suffix, or documentary claim. Read [manhwa](manhwa.md) for `manhwa_recap_v1`; read [documentary](documentary.md) and its Asset Afterlife contract for `asset_afterlife_v1`. Profile-specific factual, visual, audio, and packaging requirements take precedence over generic creative examples, never over structural, hash, scope, approval, or spend gates.

New preflight requires both `--content-profile <explicit-profile>` and `--media-workflow generated_visuals_v1`. Missing selections are errors, not permission to assume manhwa. The identity records `media_workflow` and a hash-bound `workflow_contract` with schema `goldflow_media_workflow_v1`, `id`, `version`, `stage_registry_version`, and `sha256`. Existing identities retain recorded profiles, providers, and stage contracts without implicit migration. References to historical `fast_premium_v1` behavior below apply to identities that lock it; newer identities keep their recorded `fast_premium_v2` policy.

This is not the source-footage pipeline. `source_footage_v1` is reserved and blocked for episode production; [movie/TV guidance](movie_tv.md) and the standalone footage library do not satisfy generated-image stages.

An explicitly authorized OpenArt visual restart uses the [OpenArt restart and global asset-bank workflow](../workflows/openart_visual_restart.md). It creates a new identity, preserves the approved nonvisual spine and historical attempt, requires newly generated canonical assets plus native Studio library IDs, and locks Low/1K/16:9 with per-request credit verification. It never silently changes a historical provider or makes schema validation stand in for visual review.

Packaging capability is narrower than the shared render chain: new workflow-locked non-manhwa runs stop at `upload_packaging` until a profile-appropriate adapter exists. Do not satisfy the current manhwa validator with invented betrayal/revenge metadata. Historical identities retain their existing packaging validation and approvals. The stage table below records the chain, not a promise that every content profile has a publishing adapter.

0. Obtain polished narration through the selected content-family guide. Manhwa source manufacture uses `docs/workflows/source_script_generation_workflow.md`; factual documentaries require sourced claims and the documentary evidence contract, not fiction manufacture.
1. Ingest a polished narration story into `script_clean.md`.
2. Optional script polish/enhancement only when the operator explicitly asks for it, before approval, with the resulting script treated as a new candidate for review.
3. Manual review and operator approval for the exact final script hash.
4. Script pace check for the approved script. New production scripts target 180-195 spoken WPM; `script_pace_report.json` must exist for the exact approved hash before speakability or semantic planning.
5. Targeted production-readiness and speakability QA from the approved script. These passes may suggest TTS-only fixes for known problem areas, pronunciation mappings, and risk notes, but must not silently rewrite the story. Broad speakability is optional and must be explicitly requested.
6. Semantic continuity extraction from the locked script and bibles: overlapping chunks run concurrently through the identity-locked provider-neutral planning room (eight proven Codex Medium structured workers, success-ramping in-stage to a twelve-worker ceiling in the default fast-premium profile), then one Codex evidence-constrained reconciliation canonicalizes aliases, characters, locations, props, UI, and state transitions into `story_fact_ledger.json` without inventing facts. Antigravity structured production capacity is zero until its permissions, schema-output reliability, and task-class benchmark are explicitly re-approved. Gemini Web and ChatGPT Web are reserved for deliberately named research, global creative, opening-animation, difficult hero-scene, prompt-audit, or packaging assignments; those calls are bounded and advisory rather than critical-path artifact authors. After targeted speakability passes, semantic planning and the independent voice/narration-TTS/Whisper/pace branch are parallel-ready. `fast_premium_v1` uses `goldflow run audio-semantic-fork` so synthesis and audio timing overlap semantic planning, then both branches join before timing bind.
7. Narrator-only voice plan by default. Voice planning requires current `script_speakability_report.json` and `tts_spoken_overrides.json` unless explicitly run in diagnostic bypass mode.
8. Local Qwen3-TTS 1.7B Base with the exact pinned owned Joel reference clone is the standard narration route, but the narration contract is provider-neutral. Preflight hash-binds the same-speaker delivery bank; only active references may condition production, and an unpromoted urgent/intimate/cold-reveal/restrained-grief request records the request while safely falling back to neutral-forward. Before the resident model loads, a hash-bound pre-synthesis gate must validate the complete plan, source/text lineage, exact provider payload, unit ordering and limits, pronunciation/system/UI risks, voice/model/reference identity, and authorized synthesis scope; a blocked gate spends no synthesis time. New Qwen identities synthesize deterministic length-matched cohorts of four through one resident model; every non-final cohort contains exactly four real units and the final cohort may contain one to three, with no dummy padding. Fish Audio, ElevenLabs, and other explicitly locked providers require an exact matching blind-provider-promotion receipt before production, compile the same source/caption/spoken-text IR through capability adapters, then enter through `tts import-provider` and `tts finalize-provider`; unsupported controls must be reported instead of silently ignored. Every source component must close through exact text-bearing `goldflow_spoken_text_lineage_v1` receipts before grouping, and the final provider payload must equal the lineage's exact `spoken_text`. Performance tags and delivery instructions remain structured metadata and must never enter the spoken payload. Every request and result binds model/revision, voice ID/hash, continuity contract, exact text, order, request hash, synthesis-identity hash, and WAV hash. Units stay sentence-complete, prefer 20-42 spoken words, have a 48-word soft maximum and 60-word hard maximum, and never use a continuous longform request. Punctuation may be directed without changing lexical tokens. Restore source order before QA and stitching. Never accept token-limit output, reordered/duplicate/missing units, stale identity, or stale audio. Edge editing is alignment-only: amplitude-only trimming and fades over aligned speech are forbidden, missing alignment preserves the entire unit, and joins use the authored semantic boundary class rather than a universal gap. If waveform activity extends beyond an aligned trim edge, preserve the entire unit and record the alignment conflict; activity may veto a trim but never choose a new cut point. Run unit and final-stream delivery QA, calibrated owned-reference voice-continuity QA, exact sample accounting, and two-pass -16 LUFS/-1.5 dBTP mastering. For new `fast_premium_v2` identities, the locked automated-ASR acceptance mode makes unit and full-stream QA the narration gate: confirmed omissions, insertions, corrupt edge words, or strongly unsettled raw-audio tails block exact units, while uncertain ASR differences remain recorded diagnostics without a listening approval. Historical identities with the subjective-review contract retain their original hash-bound sample manifest and listening gate. Confirmed delivery defects require exact-unit or exact-boundary repair; all accepted unit audio is hash-verified and preserved, and only the exact authorized repair units may reach synthesis. No automatic creative retry or cross-provider failover is allowed.
9. Local faster-whisper word timing on the final stitched narration. New production identities lock the measured soak contract exactly: `small.en`, CPU, `int8_float32`, `OMP_NUM_THREADS=12`, and `WhisperModel(cpu_threads=0)`; zero-duration word rows are retained as warnings rather than blockers.
10. Audio pace diagnostics from Whisper timing. `narration_pace_report_<episode>.json` must exist for the current script and narration hash before timing bind, but measured WPM is report-only and never blocks production or triggers automatic TTS regeneration.
11. Review TTS and timing artifacts before downstream production.
12. Default narrator-only longform audio bed from the canonical stitched narration report. SFX, score, ambience, and transition SFX are opt-in variants, not default requirements.
13. Visual beat planning: atomize the exact final narration into clause/sentence units bound to contiguous Whisper word indices, then let the LLM editorial director regroup adjacent atoms. The LLM owns visual job, depiction mode, physical/screen/preview/mentioned entities, location, action, and composition within the locked timing contract. Deterministic validation owns complete word coverage, order, transition barriers, stable span-derived IDs, evidence membership, cumulative `active_state_constraints`, and the hard visual-density ceiling. New `fast_premium_v2` productions never allow a closed visual hold above 8.0 seconds; 0-30 seconds caps at 4.2 seconds and 30-1200 seconds caps at 7.0 seconds. Minimum-duration and target-duration misses remain advisory. Semantic scenes remain broad story truth; local atoms and the fact ledger are cut truth. Beat-level ref hints are evidence only and never automatically promote a story cut into a reference.

Deterministic code may validate, canonicalize non-destructively, union explicit contract scene scope, and add approved source-only dependencies; it must not cap, prune, merge away, or downgrade a selected generated target. If the global director selects 96 standalone references, production generates and reviews all 96. Each selected conditioning asset must contain exactly one concept: one identity/state, environment, prop, UI motif, faction/uniform language, action/effect language, or abstract style language. 16. Generate every globally selected standalone reference in dependency order. Under a new `fast_premium_v1` identity, selected style references run first through the locked Gemini Web Imagen route and form a hard materialization barrier. After that barrier, all remaining character/location/prop/UI/faction/action anchors enter the topped-off federated pool: five persistent Google Flow worker projects plus three persistent Gemini Web worker tabs. ChatGPT Web image generation is reserved for an operator-approved exact-ID fallback, hero/thumbnail comparison, or deliberate alternative and never joins new bulk dispatch automatically. Explicit single-provider, ModelsLab, Codex Imagen, and legacy identities retain their recorded queues. Each asset is leased to one provider and receives one creative submission; it is never submitted to two providers or automatically failed over. 18. Visual prompt planning consumes approved references, current-scene facts, and visual beats. In `fast_premium_v1`, `goldflow run visual-wavefront` emits each accepted content-addressed prompt chunk atomically, sanitizes each ready scope, and appends its exact cuts to one durable episode image-work manifest while later prompt chunks are still being authored. The new-run default keeps eight Google image generations available after the Gemini style-reference barrier (five Flow plus three Gemini) while preserving ChatGPT Web for premium text work and explicit exact-ID image fallback. Each ready asset goes to the first free eligible worker and is immediately replaced with the next queue item; completion-order QA never creates a per-batch tail barrier. Explicit single-provider identities and legacy identities retain their recorded boundaries. Once the full prompt plan lands, the orchestrator starts official hardening and silent transition planning alongside the remaining image queue. Each completed scope enters a separate serialized focal/structural-QA lane, writing hash-bound risk sheets and preserving any exact-hash decisions in the cumulative review ledger. Expensive semantic audit is limited to hero, contact, identity-critical, and deterministic sample cuts, and incremental plus official QA share an exact image/contract/provider/model cache; deterministic structural raster QA still checks every cut. Any QA-passed, hash-final single-plane cut with no parallax or generated-motion dependency may prebuild its ordinary motion cache. Parallax masks and reconstructed backgrounds are created only after the actual accepted still has been inspected for separability. Wavefront prefetch never marks image generation or final image QA complete; official image materialization, complete focal analysis, structural risk decisions, motion planning, and render still validate every final hash.
19. Visual prompt harden runs directly on `section_image_prompts.json`. It validates LLM-authored prompt/ref manifests, resolves approved ref paths, strips invalid or forbidden provider inputs, deterministically normalizes explicit manifest identities and the four-reference cap, normalizes format-only prompt syntax, and writes a pre-imagegen sample sheet. Compatible creative concerns are retained as non-blocking review findings with a manual-fix-or-accept disposition; harden stops only when a cut has no usable prompt, lacks a required approved source identity, or is structurally unable to generate. It does not rewrite depicted prompt content.
20. Visual prompt review is not a default full-episode toll. Compatible harden findings may be inspected, manually fixed, explicitly accepted, or sent through exact-cut `visual review`; they do not automatically trigger planner/review retries or block image generation. Full review remains an explicit diagnostic mode and must write `review_value_report_<episode>.json`.
21. Visual transition planning with silent transition SFX by default.
22. Image generation uses one creative provider submission per reference or cut, a provider circuit breaker, immutable passed outputs, and `cut_execution_ledger.json` hash tracking. In a shared provider pool, provider selection happens when the asset is leased; a failed submission ends that item and is not reassigned automatically to the other provider. Later recovery names only the exact failed IDs and never resubmits passed assets.
23. Image output QA before render is structurally blocking and aesthetically advisory. Missing, unreadable, corrupt, wrong-geometry, stale/hash-mismatched, or duplicate-as-donor assets block their exact IDs. A reviewer may classify a confirmed story/identity-critical defect with `--critical-reject-cut-ids`; ordinary `rejected` aesthetic notes remain non-blocking. Composition taste, saliency, spelling, incidental text, mild anatomy/style concerns, and an operator's desire for a prettier alternative never invalidate a usable raster. Optional replacements stay exact-ID and preserve the accepted current image until a new one passes.
24. Animation direction is first-class for new runs. The default provider-neutral `selective_generated_video` policy makes visual-beat planning author `animation_intent` before still prompting, including starting state, one physically reachable action, terminal state and composition, terminal camera state, 5-12 second preferred duration, and a next-shot continuity bridge. Prompts compose animation-ready first keyframes. After image QA, `visual animation-plan` binds each selected intent to one accepted image hash and one standalone shot. It must never combine separate cuts into a transformation that a one-input provider would have to invent. UI/screen cuts remain eligible and generated text legibility is not a rejection requirement.
25. Google Flow video is the primary generated-motion route for new productions. It consumes only the passed image-aware animation direction plan and exactly one accepted first-frame attachment. Author the reachable terminal frame through subject state, camera endpoint, terminal composition, and next-shot bridge. Submit one creative candidate per selected motion moment with zero automatic generation resubmissions. Transport upload and status polling may continue as needed, but a generation omission never triggers another creative submission. Strip provider audio, normalize output geometry, and keep proof artifacts separate from production. Legacy LTX identities continue through the compatibility adapter without implicit migration.
26. Review every generated clip and hash-approve or reject it before motion planning. Rejected, omitted, or absent clips retain the accepted still-image motion treatment, including when no generated clip survives. Motion aesthetics never block render.
27. Selective inspected parallax runs only after image QA. The visual author may nominate separable moving frames through `motion_intent.depth_candidate`, but the actual accepted raster decides suitability. First extract a local alpha mask—a grayscale selection map isolating the intended foreground subject—and measure whether that subject separates cleanly. Only then spend on a Flux Klein rear plate, meaning a reconstructed clean background for the pixels that will be revealed when the foreground moves. Strong separations may use normal parallax; marginal but usable separations may use `approved_low_motion`; tangled or unsafe separations decline advisory and keep the original still/single-plane motion. Candidate-count and opening-window quotas are goals, not gates, and zero safe candidates is valid without a waiver.
28. Directed motion planning binds authored motion, image-QA focal overrides, approved generated-motion clips, and approved or low-motion parallax layers to accepted cut hashes. Static-share, repeated-pattern, velocity, and movement-streak findings are advisory. Only malformed, missing, stale, or hash-inconsistent motion data blocks.

30. Final QA: spot-listen narration cuts, spot-check prompt/image/ref consistency, verify transition style, verify subtitles are final-script text timed to Whisper, then `ffprobe` the final upload-safe render.
31. Package and publish, on supported manhwa or unchanged historical routes only: research current own-channel and niche outliers after final QA, create a simple title/thumbnail/description/comment package from current story truth, approve and hash-bind it, then use the Chrome publishing skill for private-first upload and separately approved release and pinned-comment actions. ## Detailed Technical and Recovery Rules

- Do not use source-seed scene annotations. Final semantic truth comes from the locked script.
- Run identity is a production gate, not an admin detail. Do not ingest, generate, render, or create new episode folders until `run_identity.json` exists and matches the command flags. Episode numbers live in `--episode` (`ep_01`, `ep_02`, etc.), not in the run/week slug. A title or operator phrase such as "Part 2" means `--episode ep_02` by default; do not create `part-2/episodes/ep_01` unless the operator explicitly approves a separate standalone run.
- New runs use `goldflow_run_identity_v2` and lock the Git commit, branch, dirty-diff hash, stage-registry version, provider/model versions, and proof scope. Production preflight requires a clean worktree. A dirty worktree may be recorded only for an explicit diagnostic/proof with both `--allow-dirty-worktree true` and `--dirty-reason <reason>`; it is never a production shortcut.
- Scope is a production gate too. If `run_identity.json`, the operator request, or the current instruction says proof, sample, first 20 minutes, first 3 minutes, first N cuts, or another bounded scope, do not generate, regenerate, render, or refresh the full episode. Select only the scoped cut IDs/artifacts, write proof reports with proof-specific names, and stop for operator approval before scaling to full production. A ledger stage such as `premium_render` does not override an explicitly bounded proof request.
- A bounded proof may reuse an audited narration/Whisper baseline only through `goldflow run import-proof-baseline --baseline-episode-dir <dir>`. The command is proof-v2-only: it trims the locked audio window, re-hashes it, scopes and re-times Whisper words, records all baseline hashes, emits zero-cost imported voice/TTS artifacts, and cannot run for production identities. When semantic planning precedes that import, pass the audited timing with `semantic plan --proof-baseline-word-timing <path> --scope-start-sec <n> --scope-end-sec <n>` so semantic extraction does not analyze the full episode.
- When a proof run validates a planner or render fix, promote the durable behavior into code, docs, and fixture tests before scaling to the full episode. Do not let proof-sidecar artifacts silently become production truth; the full episode must resume from the official `run status` stage and regenerate the official artifacts through the guarded command path unless the operator explicitly approves a scoped diagnostic bypass.
- Every run must have a visible stage ledger before work continues: current stage, required input artifact, output artifact, whether operator approval is required, and whether the artifact exists. If asked to "continue," first identify the current stage from artifacts and the ledger instead of guessing. Use `node bin/goldflow.mjs run status --channel <channel> --series <series> --week <week> --episode <episode> --format markdown` or `--episode-dir <episode-dir> --format markdown`; do not continue from memory alone.
- Blockers are not automatic rerun orders. For any blocked or missing gate anywhere in the pipeline, the active agent must inspect the blocker evidence first and choose the narrowest valid recovery: a manual structured-artifact repair, a later exact-ID/chunk repair of only affected units, a recorded waiver/bypass with evidence, or an operator hold. Manual repairs/waivers must be written to the relevant stage artifact or a `manual_blocker_triage_<stage>_<episode>.json`/stage-specific triage artifact, must explain the evidence reviewed, and must be followed by `goldflow run status`. This flexibility does not allow skipping upstream approvals, hiding missing production assets, silently changing approved creative content, or bypassing spend/scope gates.
- Codex/agent operating protocol for this repo: read the full `AGENTS.md`, run `goldflow run status`, state the current unresolved stage and next artifact, then run only the next valid workflow command unless the operator explicitly redirects. If a command would skip a missing upstream artifact, stop and explain the missing gate instead of improvising.
- The CLI workflow guard is part of production safety. Normal production commands must match the first missing `run status` stage. If `goldflow` blocks a command, do not work around it by calling scripts directly. Use `--workflow-bypass true` only for explicit operator-approved diagnostics, recovery, or one-off inspection, and state why the bypass is safe before running it.
- After every completed stage, run `goldflow run status` again, read `current_stage` and `next_command_shape`, and execute only that next command shape. Never bypass the guard just because you know the nominal order from memory.
- Guarded stage execution is append-only. Every stage and later exact-scope repair writes `execution_events.jsonl` plus an immutable timestamped report under `reports/stages/`; `production_manifest.json` is materialized from those events and `cut_execution_ledger.json`. Never replace historical batch cost/latency with the latest repair. `current_batch_status` and complete episode status are separate truths.
- Execution scope includes singular and plural cut/image/reference flags. Independent `--image-id` imports are separate scoped calls, not retries. Failed stage reports retain bounded stdout/stderr tails, and `production_manifest.json` derives accepted image completion from per-cut hashes plus QA instead of trusting stale aggregate counters.
- Compatible identity-locked planner calls are content-addressed and reused by default for semantic, visual-reference, visual-beat, and visual-prompt planning. Exact provider, model, effort policy, resolved stage effort, and prompt hash must match; invalid/empty cache entries are ignored. Pass the stage-specific reuse flag as `false` only for an intentional diagnostic refresh. Once a planner stage has passed, an unscoped rerun is forbidden even when `--resume-incomplete-chunks true` is present. Resume mode is accepted only after a failed/interrupted batch or when `planner_chunk_ledger.json` contains unresolved units; otherwise repair the small structured artifact by hand or pass exact affected IDs.
- Planner recovery is scoped-only. ## Current Production Models And Methods

- Source: polished narration prose from the operator/chatbot, with exact-hash script approval.
- Speakability: targeted-only by default; broad speakability is opt-in.
- Voice: narrator-only, with Qwen3-TTS 1.7B Base plus the pinned owned Joel clone as the default provider and a shared provider-neutral V2 quality contract for explicitly locked alternatives. Sentence-complete units prefer 20-42 words, soften at 48, hard-stop at 60, and carry separate source/caption/spoken text plus exact text-bearing component lineages; performance metadata is never spoken. Joins are semantic (continuation through reveal), speech edges are alignment-preserved, and amplitude-only trim, fades over speech, continuous longform synthesis, native/post tempo manipulation, automatic retries, and silent provider failover are forbidden. Unit and full-stream dual-ASR delivery checks, calibrated voice identity, exact order/sample accounting, exact-unit repair gates, and two-pass mastering must all remain hash-bound. New `fast_premium_v2` runs require no routine listening approval; historical locked listening contracts remain in force.
- Timing: local Whisper word timing is production truth for subtitles, SFX, score, visual beats, and render.
- Audio planning: identity-locked planning room by default, with Codex as final local reconciler. If automated planner calls are unavailable, an agent-authored manual plan may be written with explicit provenance, current source hashes, and Whisper timing.
- SFX generation: ModelsLab `/api/v7/voice/sound-generation` assets are allowed after an identity-locked ChatGPT Web/Codex/local-Qwen or explicitly agent-authored plan. SFX events must use locked asset paths before mix.
- Ambience generation: also ModelsLab sound-generation, represented as loopable SFX events with `recurrence_class: "ambience"`, `loop: true`, short generated `asset_duration_sec`, and longer timeline `duration_sec`.
- Score generation: retain the identity-locked provider and model. Local ACE-Step 1.5 is the standard local score route (`acestep-v15-turbo` plus `acestep-5Hz-lm-1.7B`). Whether to use a bed, drops, or no score—and any cue-count targets—comes from the selected content-family guide and approved audio intent, not a universal retention recipe.
- SFX-only mix: use `--sfx-only true` during audio enrichment and `--skip-score true` during longform-bed when the story is stronger with clean narration and punctuation SFX instead of score.
- Default image generation for new `fast_premium_v1` identities is `federated_google_web_image_pool`. Selected Gemini style anchors run before dependent refs/cuts, then five Flow plus three Gemini slots stay topped off while later prompt chunks arrive. ChatGPT Image is reserved for operator-approved exact-ID fallback or deliberate alternatives. Every asset receives one provider lease/submission, every result records its actual provider/model and exact fail-closed reference receipt, and no failure moves automatically to another provider. Explicit single-provider, ModelsLab, Codex Imagen, and legacy identities retain their locked lanes.
- Render: one continuous mixed audio track, phrase-aware final-script subtitle text timed by Whisper, yellow subtitle text with a small black outline and no background box. Visual prompt authoring writes a beat-level `shot_manifest.motion_intent` naming the focal subject, normalized anchors, restrained scale, easing, behavior, editorial reason, and a conservative `depth_candidate` decision. A cut may optionally carry 2-5 normalized `motion_keyframes` when it earns multi-phase timing. Default to hold, one acceleration-smooth ease-in-out move, and final hold; do not use quick scale overshoot-and-settle bounce as generic impact. Keyframes are selective editorial direction, not mandatory movement on every still. Static share, first-minute contrast, and uninterrupted-movement streaks are review diagnostics only; deterministic code never rewrites or blocks authored cuts to meet those aesthetic targets. Run `goldflow visual motion-plan` only after image QA and the parallax decision stages: authored intent is the baseline, an explicit image-QA focal override may supersede it after inspecting the real frame, and only legacy/missing authored intent uses conservative shot-staging fallback. Missing focal intent becomes a smooth static hold; production motion must never use hash-random direction fallback. `smooth_subpixel_ken_burns` is the locked default premium renderer for new preflights. It executes directed intent and keyframes with a cubic per-frame perspective transform at 1080p/60 fps, avoiding integer `zoompan` micro-jitter without a heavy 4K oversample. `smooth_fast_ken_burns` is an explicit faster integer-sampling fallback, and `fill_ken_burns` is legacy/diagnostic only. Render refuses a v2 profile that differs from `run_identity.render_profile` unless the operator explicitly approves a diagnostic bypass.
- Premium motion benefits from contrast, but contrast is not a production gate. Leave readable reaction, tension, and UI inserts as true static holds when the composition already carries the beat; use one restrained move for ordinary directed shots; and spend on layered 2.5D wherever an image-QA-passed still actually separates cleanly. A true static hold cannot be a parallax candidate because layered depth is movement. The LLM may nominate candidates, then local foreground-mask evidence from the accepted raster classifies each as normal motion, `approved_low_motion`, or advisory decline before any Flux Klein background reconstruction is requested. Run `goldflow visual parallax-assets`, inspect its source/mask/foreground/background review sheet, and record explicit decisions for produced candidates. Zero safe candidates passes without a waiver. Approved layers use the `foreground_cover` contract: foreground and background keyframes share anchors/timing/easing and foreground scale never falls below background scale. Lateral layer drift remains forbidden because it can reveal an unreconstructed area or duplicate silhouette. A weak mask or unsafe rear plate declines advisory and the cut keeps its single-plane move or static hold.
- Render timing is absolute. Preserve the `start_sec` timeline from `section_image_prompts_hardened.json` / `visual_beat_plan.json`; do not globally scale image durations to fill the audio. If the visual plan has a gap before the next cut, hold the current image until the next cut's real start time or add new visual beats/images in a planning pass. Never fix timing drift by stretching all cuts. Each generated motion clip must be duration-probed immediately; abort on malformed clips instead of continuing a long render.
- Render applies every selected FFmpeg `xfade` boundary across the full timeline using bounded contiguous transition segments; every unselected boundary remains a hard cut. It writes per-frame motion traces and blocks unplanned within-segment reversals, excessive keyframe velocity, discontinuities, malformed duration, stale image hashes, or planned/applied transition-count mismatches. Reviewed direction reversals are structurally valid, but generic scale bounce is not the default. Do not ask the audio SFX planner to author generic edit whooshes/pops as narrative SFX. The visual transition planner decides whether a boundary earns SFX and chooses a compact editorial family (`swipe_up`, `swipe_down`, `lateral_whoosh`, `manga_snap`, `impact`, `system_scan`, or `memory_wash`); deterministic edit code resolves that family only to an approved available SFX-bank asset. Narrator-only runs keep transition SFX disabled unless the operator explicitly requests a separately named proof/variant and render records `--allow-transition-sfx-on-narrator-only true`.
- Opening retention QA reviews visual cuts, transition SFX, and score drops together. A visible cut every 2-4 seconds in the first 30 seconds and every 4-7 seconds from 30-180 seconds are editorial targets when narration supports them, never render or planning blockers. Transition SFX should start within roughly one frame of selected visual cuts, and score drops should land on hook/ramp turns that need sustained emotion or threat. Record sparse visual change as an advisory for the next editorial decision; do not automatically regenerate or replan a structurally valid beat plan.
- Render QA is mandatory before treating an MP4 as publishable: run `ffprobe` for duration, fps, codec, pixel format, audio codec, and size; audit rendered cut times against transcript/visual-beat `start_sec`; extract final QA frames/contact sheets; and spot-check prompt/image/ref consistency. A final MP4 with the right total duration is not enough if individual images drift from the story.
- A failed render may resume with `render start --render-recovery-triage <episode-local-json>` only after manual diagnosis and a reviewed `goldflow_failed_render_resume_v1` receipt binds the exact failed report, corrected renderer, and unchanged production source artifacts. This preserves cached motion and failure history, does not bypass earlier stages, and cannot replace a passed render. Validate captions before motion rendering; zero-duration Whisper groups must retain their approved script words in adjacent anchored captions.
- Subtitle grouping may merge accidental one-to-four-word incomplete fragments into an adjacent phrase only when the combined caption stays at most about twelve words and 3.4 seconds. Preserve deliberate short emphasis such as "No!" or "Two fingers rose." and never change approved script words or Whisper timing anchors.
- Subtitle timing must account for approved TTS-only spoken expansions while preserving script-faithful text. In particular, a caption token such as `0X` remains `0X` on screen but binds to the Whisper span for “zero times”; the expanded speech must not shift that caption onto the following phrase.
- Complete final QA through `goldflow final qa --approve true --note <evidence>`. `run status` accepts only a passed current `final_qa_<episode>.json` whose render-report hash, final-video hash, and render source hashes still match; a QA-shaped filename is not completion evidence.
