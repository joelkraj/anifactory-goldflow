# Manhwa Recap Guidance

Required for `content_profile: manhwa_recap_v1` and manhwa source development. Read this document completely, then [the generated-visuals operating contract](generated_visuals.md) before episode operations. Before source-development calls, also read [the manhwa source-script workflow](../workflows/source_script_generation_workflow.md).

These fiction, recurring-character, style, graphic, and packaging rules apply only to the manhwa content family. They do not apply to Asset Afterlife, lost-luggage documentaries, or movie/TV criticism. Existing manhwa behavior and recorded provider identities are preserved.

New preflight must explicitly select `--content-profile manhwa_recap_v1 --media-workflow generated_visuals_v1`. `source manufacture` is the manhwa-only source-development route; it is not a factual research writer or movie/TV recap planner. Source development remains separate from production and stops for exact-script approval.

## Authority and Existing Runs

The locked content-profile configuration and run identity govern an existing episode. Examples below preserve the detailed manhwa operating history; they are not instructions to start the named episode, enable an optional audio variant, replace approved assets, or rerun a passed stage. Structural/hash/scope gates and exact-ID recovery in the generated-visuals guide remain binding. Creative preferences never authorize automatic generation retries.

## Source Development and Dramatic Contract

- Source scripts should arrive as spoken narration prose only. New source development defaults to `direct_manufacturer_v1` with the September 4 `three_56_pro_v1` writer policy: one GPT-5.6 Medium title-pool call and one fresh Medium shortlist call use measured own-channel winners and external outliers; the operator approves one exact title/premise; one Medium call fills the operator's versioned manufacturing template; exactly three independent authenticated GPT-5.6 Sol Web Pro writers receive that same prompt in fresh contexts, with concurrency three and 15-second staggering. No GPT-5.5 drafting for new work. One fresh Medium selector compares the three complete blind scripts by calibrated expected average percentage viewed and saves the winner byte-for-byte. Word count is a target, not a selector or release gate. Every browser page must select and verify its exact model and visible effort before submission. Historical six-draft portfolios retain their original identities and receipts.
- The default source chain is `source manufacture ideate -> operator premise approval -> source manufacture prepare -> source manufacture write -> source manufacture select -> source manufacture improve -> operator exact-script review -> run preflight/ingest`. The operator-approved improvement loop uses one Medium editor, then one High editor only if the first challenger wins; comparisons remain Medium. Each pass privately diagnoses and writes one complete challenger, preserves length and the incumbent, and stops on its first loss. Two rounds maximum by default, no automatic retries, no separate critique stage, no Pro editing, and no deterministic prose patches. `--max-rounds 1 --edit-efforts medium` deliberately limits the loop. No mandatory treatments, architecture, Story Truth, writer packets, or extra diagnostic chain. The pipeline records prompt, draft, selection, model, transport, effort, hashes, and timing. `first_class_story_room_v4` remains readable and may run only when the operator explicitly requests the advanced research/diagnostic room.
- Self-learning changes the versioned manufacturing prompt only through one concrete, operator-approved addendum backed by upload evidence. One upload may propose a change but cannot silently mutate the template. Prefer one controlled prompt change with a validation and rollback plan over adding another mandatory model stage.
- Supporting-character name freshness uses a release-derived, episode-count TTL ledger, not a permanent blacklist. New architectures default to a 12-release window: recent reuse receives a decaying soft preference against reuse, the weight reaches zero outside the window, and a story-native reuse remains allowed with rationale. Joey Manhwa and approved recurring-series characters are exempt. The ledger is snapshotted before architecture so later releases cannot silently change an approved room's inputs.
- Name-familiarity weighting never applies to sequel continuations. Pass `source architecture --continuation true` for Part/Episode 2 or later; Part 2+, Episode 2+, and EP 2+ titles also trigger a safety-net exemption. Preserve established cast names exactly across continuation episodes instead of treating continuity as stale reuse.
- Source opening delivery is chosen before prose. New retention-room blueprints select `linear_title_event`, `direct_premise`, or `outcome_choice_rewind`. The outcome-choice-rewind pattern uses one concrete later result, one satisfying Joey action or refusal, and one clean rewind that adds cause rather than replaying the preview. The first thirty seconds may introduce at most one new proper name and two unexplained story terms. This is a language-density and comprehension contract, not a mandatory first-person gimmick; use it only when it makes the approved package easier to understand immediately.
- Source ideation author and independent-selector calls default to a sixty-minute Web timeout. If the author has a passed prompt/output hash and only the selector fails or is throttled, recover with `source ideate --resume-selector true` after the shared cooldown. This path must verify and reuse the exact passed author artifact and receipt; never pay for or accept a second author submission merely to repair the selector stage.
- Genuine K-drama/manhwa style is a causal story requirement, not decorative emotion or forced romance. Preserve Joey's believable initial wound, then make decisive evidence change behavior: define the required update, irreversible boundary, and strategic-contact rule before prose. The system supplies leverage, information, options, or constraints; Joey owns goals, moral judgment, tactics, and decisive action. Most movements change both the external situation and a relationship, belief, or emotional obligation. A rare causal bridge may carry one durable external or knowledge change without inventing a false emotional turn, but bridges are never consecutive and may not become procedural filler. Recurring characters need private wants, fears, contradictions, useful capabilities, and choices that can alter Joey's plan without taking his story ownership. Money, ranks, systems, contracts, hearings, acquisitions, transfers, training, and institutions are leverage rather than drama; compress routine procedure and dramatize the human betrayal, temptation, discovery, alliance, sacrifice, refusal, or consequence around it.
- Chatbot prompts are versioned in `docs/prompts/`; improve those templates before adding deterministic source-prose repair to the pipeline.
- Source-room ledgers are backstage memory, never narration style. Unless an approved package explicitly sells courtroom, corporate, political, or administrative fantasy, allow at most one extended institutional set piece. Repeated hearings, ledgers, audits, councils, contracts, permissions, testimony, authentication, governance, and official review are release defects even when logically coherent. Compress them to causal bridges and require visible character conflict, ingenious premise-native power use, desirable superiority, relationship consequence, or spectacle to carry the entertainment and decisive victories.
- Source-room revision and audience calls share one rolling request budget. The fixed viewer panel uses three topped-off workers with 15-second input staggering, but the measured safe budget is three new source-room starts per 15-minute rolling window. A preceding revision consumes one of those shared start slots until it leaves the window; panel concurrency is not independent provider capacity.

## Manhwa Audio Direction (Opt-in Variants)

- SFX-only is an approved production route for narration-driven humiliation/system stories. Run audio enrichment with `--sfx-only true`, generate no score beds, and mix with `--skip-score true` so the final audio is narrator plus selected SFX only.
- SFX should be selective and beat-anchored. Prioritize system pings, phone buzzes, paper/card handling, glass/banquet objects, room hushes, laugh ripples, applause turns, wealth-reveal impacts, and a few signature transaction confirmations. Avoid constant literal Foley under every sentence.
- Score should be moment-directed, not automatic. For runs where the story is stronger without continuous music, use `--score-mode drops_only`: `score_chapter_plan.json` stays empty and `score_drop_plan_<episode>.json` places Whisper-timed local ACE-Step scoring cues only on focal drama, hype, reversal, reveal, payoff, escape, and cliffhanger beats. The longform mixer fades each drop in/out; if chapter beds exist, it ducks overlapping beds instead of stacking uncontrolled volume. Target roughly 20-35 score drops by default, but explicit "scoring team" or loud retention runs should use `--retention-mix true` or raise the cap with `--score-target-drops-max`/`--score-target-drops` and hold major moments for 8-18 seconds. For "sense/loud/final mix" retention runs, it is acceptable to push to roughly 60-80 score drops with frequent dramatic score punctuation. Keep score separate from physical SFX and intentional enough that each cue feels placed.
- SFX should be dense in the opening hook. For the first 30 seconds, target at least 14 and ideally 18-24 audible cues where narration and edit timing support it: deterministic transition accents such as swipe-up flash, swipe-down whoosh, hard scene-card whoosh, impact flash, dark-paper title snap, and manga-panel slide should be bound by the visual transition plan and render layer to actual cut timestamps, while LLM-authored narrative SFX should cover system/ledger pulses, room hushes, phone buzzes, transaction chimes, shame hushes, and concrete story/object sounds. After the hook, keep SFX consistently present but selective and beat-anchored. The Anti-Simp dense-audio pass used a successful target shape of about 260 narrative SFX/ambience cues plus deterministic transition accents and 78 score drops for a 62-minute episode; treat that as a loud retention reference point, not a mandatory count for every runtime.
- Loud retention mixes should not use the old quiet `--sfx-boost-db -4` setting. Start with `--score-drop-boost-db 3` to `5`, `--signature-sfx-boost-db 1` to `3`, `--incidental-sfx-boost-db 1` to `3`, and `--ambience-sfx-boost-db -2` to `0`, then verify against narration intelligibility. Bad-sounding SFX must be regenerated from concrete prompts, not hidden by lowering the whole SFX layer.
- For humiliation/system-finance stories, consider an SFX-only audio pass before committing to score. Clean narration plus selective SFX may retain better than continuous beds.

- Score generation: prefer local ACE-Step 1.5 for moment score drops and any intentionally chosen chapter beds; current default local model pair is `acestep-v15-turbo` plus `acestep-5Hz-lm-1.7B`. Score drops are short Whisper-timed ACE-Step riser/hit accents for 20-35 drama, hype, reveal, and payoff beats, mixed by ducking the base score bed if one exists.
- Use the optional score-drop layer when the run needs retention accents. Normal runs can use twenty to thirty-five Whisper-timed local ACE-Step riser/hit accents; loud retention/final-review runs should use chunked score planning around 60-80 held drops with 8-18 second durations when the operator asks for more score punctuation.

## Manhwa Visual and Reference Direction

- Editorial beat jobs are mandatory. Each cut should have a purpose such as premise image, humiliation image, system/quest reveal, reaction shot, remote witness cutaway, chat/UI insert, location transition, physical entrance, consequence, status turn, payoff, or cliffhanger question. Split on story turns: new location, named character entry, system message, public-audience/status-metric change, emotional pivot, objective change, threat reveal, public witness reaction, and hard scene transition.
- The first 20 minutes are the high-density retention runway. Treat 0-30 seconds as the dense cold open, then retain fast visual turnover through 20:00. For any story with an early hidden power, public humiliation, ranking/status rule, regression, system, or major premise reversal, aim for the title promise by 0:30, the first visible proof/payoff by about 0:45, the core status or power rule explained before or around that payoff, and the next major arc underway by about 1:00 when the script supports it. Visual beat planning uses `--beat-timing-enforcement hard_max --hook-duration-sec 30 --hook-target-beat-sec 3.2 --hook-max-beat-sec 4.2 --retention-ramp-sec 1200 --ramp-target-beat-sec 6 --ramp-max-beat-sec 7 --target-beat-sec 7.5 --max-beat-sec 8`. Do not let the opening sit on slow Ken Burns images while audio drops are firing.
- Real named public creators, streamers, celebrities, or influencers whose likeness matters need source-face anchors before character-state refs are generated. Use operator-provided, approved, or rights-cleared source portraits as face-only identity anchors, then generate anime/manhwa character-state refs from those anchors. Do not rely on text-only phrases such as "Kai-inspired" or "Agent00-inspired" for production likeness. Source images supply facial likeness only; the character-state ref supplies wardrobe, pose, body state, and episode styling.
- Ritual/document close-ups should use physical seal glow, ink, brush water, paper, and altar light before supernatural UI. Do not let a ledger/UI panel turn a prop insert into a screen shot unless the beat explicitly needs UI.
- If a generated still shows subject fusion, miniature heads, duplicate protagonist faces, a face embedded in another body/prop, an unplanned bubble/caption, or a UI panel covering a face, treat it as a generated-still failure. Intentionally authored `narrative_overlays` are part of the requested image and remain valid when their bubble, reaction styling, or RPG text is compositionally readable. Regenerate failed cuts from a hardened prompt with explicit subject count, primary-subject focus, separate bodies, clean graphic placement, and a single coherent manhwa frame.
- Scene prompt bodies should carry concise anime/manhwa style intent without long repeated boilerplate. Use a short phrase such as `16:9 landscape anime/manhwa frame` when style would otherwise be ambiguous; do not append phrases like `clean line art`, `cel-shaded characters`, `cinematic webtoon lighting`, or `non-photorealistic painted background` to every cut. Background population is an LLM editorial decision made from exact local narration and the cut's visual job. The author may choose detailed people, soft-focus extras, organized groups, silhouettes, foreground reactions, distant activity, or no population when that is the strongest truthful depiction. Deterministic code validates evidence and identity membership but does not prescribe, add, remove, restage, or rewrite that choice. Composition is beat-authored, not globally defaulted: the planner may choose close-up, insert, medium, over-shoulder, wide, manga panel, split-screen, or another framing only when that shot scale serves the current visual job and narration excerpt. Do not impose a universal wide/full-frame/medium-wide default. Reference images guide identity, wardrobe, style, UI, props, and effects; they should not be described as visible reference panels, sheets, or background content inside the final cut.
- Image models should not be asked to render dense text blocks. Short, large, image-native lettering is a standard part of this lane: RPG rank/status/quest text, manhwa speech or thought bubbles, and manhwa reaction typography. Keep source-required multi-line text in `ui_text_on_screen` metadata, but materialize any short story-critical phrase that must appear in the still directly in provider prose.
- `narrative_overlays` is a standard visual-authoring decision for every cut, and most cuts should integrate one. Use `rpg_game_text` for progression receipts, `speech_bubble` or `thought_bubble` for additive dialogue/subtext, and `manhwa_reaction` for shock/rage/dread/comedy/impact treatment. Reserve `[]` for purposeful clean establishing, dense-action, or emotional frames where lettering would weaken the image. State the new value in `information_delta` and normally use one dominant 2-10-word graphic.
- Dialogue-heavy beats still require strong silent acting through posture, eyelines, expression, hands, props, and blocking. An authored speech/thought bubble adds subtext or pressure to that acting; it does not replace the visual performance or merely transcribe narration.
- Recurring protagonists and other reusable cast belong in `canonical_entities.json` and should be referenced by stable ids. Joey is a canonical recurring MC, but literal episode sentences containing Joey are still episode contamination and must not be embedded in code. Generic rules should consume canonical entity ids, not character-name prose.
- Body-state proof beats in transformation stories should not repeat the next workplace/action shot. If the beat is about weight, shirt tension, grooming, posture, or visible physique, the LLM should stage a close body-detail or mirror/elevator/lobby composition that proves the current state before moving into the next job/gym/action location.
- Phone, voicemail, cold-email, and remote-sales-call cuts may use intentional manga-style split panels when that improves readability. Keep panel roles controlled: the largest physical panel shows the local protagonist in the real current location, while small secondary panels show device close-ups, contact avatar icons, envelope icons, phone UI shapes, opportunity badges, or abstract call-flow cards. Do not stage the remote caller as a physical person, full portrait, separate office scene, or second character unless the script beat physically places that person in the room. The failure mode is uncontrolled panels that invent people, duplicate the protagonist, add speech bubbles, or turn a remote mention into a physical scene.
- Transformation stories need enough protagonist state refs to show trajectory. Do not reuse a rain-night/discarded outfit ref for later self-improvement beats. Add intermediate refs such as early discipline, emerging founder, and final owner when wardrobe/body state changes are part of the viewer promise.
- For adult attraction/status stories, female character refs and visible-scene prompts should carry strong non-explicit visual appeal: striking faces, glossy hair, polished makeup, flattering story-appropriate outfits, conventionally attractive adult proportions, full bust, curvy hourglass silhouette, graceful waist-to-hip shape, and glamorous/high-status anime manhwa energy when the scene calls for it. Keep the language adult-coded and avoid childlike features, nudity, lingerie, explicit posing, or photorealism.
- Character refs should explicitly state that the style reference is for rendering only and that face, body, silhouette, hair, wardrobe, and expression come from the character prompt. For female adult refs, emphasize beautiful facial features, polished styling, confident silhouette, full-bust curvy hourglass adult figure, and story-appropriate attractiveness in non-explicit fashion terms.
- For real public creator likenesses, reference planning must prefer `base_identity_ref_id` plus `identity_usage: "face_only"` from the source-face anchor. The visible state ref should still be a single-person, plain-background, landscape anime/manhwa card. If no approved face source exists, block or flag for operator review instead of inventing a generic lookalike.

## Manhwa Packaging

- Thumbnail packaging is separate from production scene imagegen. Use `docs/prompts/youtube_ctr_packaging_director_v1.md` after final QA and ground every package in at least one measured own-channel outlier plus recent measured niche outliers. Titles must explain the concrete betrayal and revenge/takeback, stay within one hundred characters, and end with `| Manhwa Recap`.
