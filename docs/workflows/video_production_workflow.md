# Goldflow Video Production Workflow

This is the detailed operational path for `media_workflow: generated_visuals_v1` in the distilled Goldflow repo. Read [the generated-visuals contract](../pipelines/generated_visuals.md) and the selected [manhwa](../pipelines/manhwa.md) or [factual-documentary](../pipelines/documentary.md) guide before operating on an episode.

This document shares technical stages, not one global editorial formula. Directions explicitly marked **Manhwa-only** do not apply to documentary content. The embedded content profile governs visual jobs, style, factuality, audio treatment, and packaging. Asset Afterlife requires its [evidence/profile workflow](asset_afterlife_profile.md), not fiction manufacture. The reserved `movie_tv_commentary_v1` / `source_footage_v1` lane remains design-only and production-blocked; [standalone footage clipping](footage_clipping_workflow.md) cannot satisfy this registry.

New workflow-locked non-manhwa runs stop at an explicit unsupported-packaging gate until a profile-appropriate adapter is implemented. Shared rendering does not imply that the current manhwa packaging schema supports documentaries. Preserve historical packaging validators and approvals; never invent betrayal/revenge metadata or bypass the new route boundary.

New preflight requires both `--content-profile <explicit-profile>` and `--media-workflow generated_visuals_v1`. A missing flag is an error; choose explicitly from the operator's stated content/format intent or ask if it is ambiguous. New identities bind `media_workflow` plus `workflow_contract: { schema: "goldflow_media_workflow_v1", id, version, stage_registry_version, sha256 }`. Existing identities are not migrated: a missing historical workflow field retains the legacy generated route, and recorded profile/provider/motion/scope contracts remain authoritative. Historical provider/profile examples below do not override an active identity.

## Core Principle

The approved narration script is production truth. The pipeline should extract, time, voice, score, visualize, and render that truth. It should not creatively repair a weak source script after approval.

Every guarded stage appends start/completion events to `execution_events.jsonl`, writes an immutable stage report, and refreshes `production_manifest.json`. Later exact-scope repairs retain their own cost, latency, cache, scope, and attempt records; a repair never erases prior failure evidence or regenerates passed work.

Planner calls use exact content-addressed cache reuse by default. Provider, transport, model, effort policy, resolved stage effort, and prompt hash must match; malformed cached output is ignored, and `planner_chunk_ledger.json` records each accepted or failed packet. Every planner unit gets one creative attempt. Passed packets remain immutable; a failed packet records only its exact chunk/scene/atom/beat/ref scope for a later explicit repair. Use `goldflow run advance` to walk automatic stages without drift. With the default locked `fast_premium_v1` profile, normal planner/media/render spend and the self-validating beat-plan approval are already authorized; the driver still stops at reference-plan/image approvals, critical blockers, stale artifacts, manual command shapes, or the single stage-attempt boundary.

Planner recovery is scoped-only. Once a planner has executed, another unscoped planner invocation is refused unless it names exact scene/cut/beat/reference IDs or uses a stage that explicitly permits `--resume-incomplete-chunks true`. Visual-prompt planning never uses an unscoped resume: a partial failure writes a complete blocked base plan, preserves passed chunks, and `run status` emits exact failed `--cut-ids` recovery. Cache-disabled planner retries are blocked. `run advance` stops on blocked, failed, or stale planner state so the agent can inspect the evidence, prefer a small hand repair, or issue the narrowest scoped recovery.

Historical `fast_premium_v1` identities target 300-420 minutes from preflight to private-ready output. It exposes the eight-phase agent-director view while retaining the detailed stage ledger underneath. Its recorded identities lock planning-room v2, one resident local Qwen3-TTS model processing deterministic length-matched cohorts of four, the federated web-image pool, three generated-motion slots, and four smooth-render workers. Routine structured planning starts at the proven eight Codex Medium slots and success-ramps within each stage to an identity-locked twelve-slot ceiling; Antigravity production capacity is zero until its permissions, structured-output reliability, and task-class benchmark are re-approved. Gemini Web and ChatGPT Web receive only explicitly named bounded research or premium/advisory assignments such as global creative direction, opening animation, difficult hero scenes, prompt audits, and packaging. Still images keep five persistent Flow projects plus three persistent Gemini tabs topped off automatically; ChatGPT Image is an explicit exact-ID fallback or deliberate alternative. Flow video is the default selective generated-motion route. Every media asset receives one provider-selected creative submission, passed artifacts remain immutable, and later recovery names only exact failed IDs. Legacy identities retain their recorded routes.

Use `goldflow run director --episode-dir <episode-dir> --action status` as the normal agent-facing view. `--action advance` performs one guarded advancement. `--action babysit` acquires a singleton episode watcher, waits at every operator/checkpoint gate, never auto-approves, stops on blockers, and resumes routine work only when the hash-bound ledger signature changes. Before spawning advancement it atomically records the episode/stage dispatch key, execution-event cursor, in-flight phase, and child PID. A restart restores the consumed dispatch only from exact bindings and fails closed on an ambiguous spawn window, live/stale child, unreadable state, or open execution, so it cannot submit the same unchanged stage twice. Record an approved macro checkpoint with `--action checkpoint --checkpoint <id> --approve true --approved-by <name> --note <evidence>`. Phase eight reads the non-blocking 24-hour, 72-hour, and 7-day analytics follow-up artifacts and remains active until they are captured, without preventing the next episode from starting.

Each director state change writes the current performance audit. Keep `--action babysit` active so an approval, manual repair, exact-scope recovery, or asynchronous completion immediately re-enters guarded advancement. Use `goldflow run performance-audit --episode-dir <episode-dir>` to inspect active-union time, queue/approval/blocker gaps, unexplained automatic-stage idle, provider failures, and target overrun; unexplained idle is a defect to remove, not a reason to weaken quality gates.

After targeted speakability, `goldflow run audio-semantic-fork` executes semantic extraction in parallel with voice planning, narration synthesis, local Whisper timing, and audio pace diagnostics. The stage registry declares the two branches independently ready and joins them at timing bind. Concurrent provenance is output-owned, so semantic execution cannot claim or double-count audio reports and audio execution cannot claim semantic artifacts.

Planner recovery is scoped-only. A first attempt may plan the requested production scope; after a planner passes, the CLI refuses an unscoped rerun. `--resume-incomplete-chunks true` is valid only when execution history or `planner_chunk_ledger.json` proves a failed, interrupted, or unresolved batch. For a small defect, inspect and repair the structured artifact directly, record the triage, and rerun only downstream validation. For a creative repair, pass the exact affected scene, beat, cut, image, or reference IDs.

After generated references are approved, `goldflow run visual-wavefront` starts content-addressed visual prompt planning and watches for accepted prompt chunks. It hardens each ready scope and atomically appends its exact cut IDs to one durable episode image-work manifest, keeping the identity-locked federated pool topped off while later chunks are authored. The stream seals only after planner emission ends; completion-order QA can start immediately and does not wait for a batch tail. An interrupted unsealed stream fails closed against a competing repair manifest. Reference dependencies still form hard barriers: selected Gemini style anchors precede dependent identity/location anchors, and approved identities precede dependent cuts. Important accepted stills may enter Flow video immediately after image QA while later stills continue. Explicit single-provider or ModelsLab routes remain identity-locked overrides.

Each completed image scope is handed to a separate serialized incremental-QA lane while provider slots keep working. That lane performs hash-bound focal analysis and structural QA, writes immediately inspectable advisory contact sheets, and preserves exact-hash decisions without deleting earlier passed work. Structural raster checks still cover every cut. The expensive semantic model is reserved for hero, contact, identity-critical, and deterministic sample cuts, and incremental and official QA reuse rows only when the image hash, compact contract hash, provider, model, effort, and audit version match exactly. Every readable, current, structurally valid cut remains accepted. A cut blocks only for deterministic structural corruption/provenance failure or an explicit reviewer-confirmed story/identity-critical failure.

The wavefront may also prebuild ordinary motion clips for every accepted, hash-final single-plane cut whose inputs are final and whose treatment does not depend on parallax or generated video. These clips use their final timeline index, transition tail, image hash, render profile, and motion cache key. Official motion planning and render remain authoritative: any later change causes a cache miss and a normal scoped rebuild. Independent transition groups are likewise content-addressed and bounded-concurrent. Prefetch reports are immutable and costed, but they never satisfy official image generation or image QA. Final materialization and QA still recheck every cut hash.

## Full Flow

0. Run identity preflight.
   - Before ingest, explicitly select the content profile and `generated_visuals_v1` media workflow, then lock channel, stable series slug, stable run/week slug, episode id, title, source path, image provider intent, and proof-vs-production intent in `run_identity.json`. The versioned workflow contract is hash-bound with the identity.
   - `goldflow_run_identity_v2` also records Git commit/branch/dirty-diff hash, the stage-registry version, provider/model locks, and an explicit full-episode or bounded proof scope. Production requires a clean worktree. Dirty execution is allowed only for an explicit diagnostic/proof with `--allow-dirty-worktree true --dirty-reason <reason>`.
   - Episode numbers live in `--episode`, not in `--week`. A sequel title such as "Part Two" implies `ep_02` by default. Do not create `part-2/episodes/ep_01` unless the operator explicitly approves a standalone run.
   - Required command shape:
     `node bin/goldflow.mjs run preflight --content-profile <content-profile> --media-workflow generated_visuals_v1 --channel <channel> --series <series> --week <stable-run-slug> --episode ep_02 --title <episode-title> --source <chatbot-output.md> --planning-provider planning_room --planning-effort-policy planning_room_stage_routed_v1 --image-provider federated_google_web_image_pool --google-flow-plan ULTRA --google-flow-model "Nano Banana Pro" --google-gemini-plan Ultra --google-gemini-model "Nano Banana 2" --audio-target narrator_only --target-wpm-min 180 --target-wpm-max 195 --production-profile fast-premium --run-intent production`
   - Ingest must refuse to run without a matching `run_identity.json` unless a diagnostic bypass is explicitly used.
   - A bounded proof uses `--run-intent proof --proof-scope 0-300` (or explicit start/end flags) and must write isolated proof artifacts.
   - Audited narration/Whisper reuse is explicit: `goldflow run import-proof-baseline --baseline-episode-dir <dir>` is restricted to v2 bounded proofs, trims/re-hashes the locked window, re-times Whisper words, records source hashes, and reports zero provider calls. Scope semantic planning first with `--proof-baseline-word-timing`, `--scope-start-sec`, and `--scope-end-sec`; never analyze or regenerate the full episode for a bounded proof.
   - Before any resume or "continue" request, run the artifact-backed ledger:
     `node bin/goldflow.mjs run status --channel <channel> --series <series> --week <stable-run-slug> --episode <episode> --format markdown`
   - The agent must continue from the first missing stage in that ledger. If the next requested command would skip a missing upstream artifact or operator approval gate, stop and explain the missing gate.
   - Blockers are triage points, not automatic rerun commands. At any stage, inspect the evidence and pick the narrowest valid recovery: patch a structured artifact by hand, make one later explicit submission for only the exact failed IDs/chunks while preserving all passed work, record a manual waiver/bypass with evidence, or hold for operator decision. Record manual dispositions in the stage artifact or a `manual_blocker_triage_<stage>_<episode>.json`/stage-specific triage artifact, then rerun `goldflow run status`.
   - Manual triage must preserve production gates: do not skip operator approvals, proof-vs-production scope, missing required media assets, stale source hashes, or spend-sensitive generation guards. Do not use manual repair to rewrite approved creative prose or quietly change story truth.
   - `bin/goldflow.mjs` enforces the ledger for normal production commands. A command that belongs to a later stage should fail before it spends media budget. Do not bypass the guard except for explicit diagnostic or recovery work approved by the operator.

1. Generate or obtain a polished source narration script.
   - Follow the selected content-family guide: manhwa uses `docs/workflows/source_script_generation_workflow.md`; factual documentary uses `docs/pipelines/documentary.md` and its sourced evidence contract. `source manufacture` is manhwa-only.
   - Manhwa-only direction: Use `docs/prompts/manhwa_recap_chatbot_prompt_v5.md` with the `CONVERSATIONAL WINNER` profile for manhwa recap source generation unless the operator selects another documented profile.
   - The source should be spoken narration prose only.

2. Manually review the source script before ingest.
   - For documentary work, separately review factual claims against actual sources and their jurisdiction/date/company scope. A structurally valid or hash-bound evidence ledger does not establish claim truth.
   - Manhwa-only direction: Review the exact candidate manually. `goldflow source audit` or `docs/prompts/manhwa_recap_comment_criticism_release_gate_v1.md` may create a non-blocking review log when useful.
   - Operator-release the exact approved package and narration hash. Automated review labels never trigger regeneration or block ingest.
   - Watch for narrator self-reference, headings, bracketed notes, screenplay labels, production notes, delayed title payoff, and unnatural UI dumps.

3. Ingest source.
   - Writes `operator_source_story.md`, `script_clean.md`, `source_story_ingest_report.json`, and `operator_story_lock.json`.

4. Optional pre-lock script polish.
   - Only run if the operator explicitly asks.
   - Any changed script becomes a new candidate and needs a new exact hash approval.
   - Do not treat broad LLM enhancement as a default production stage.

5. Manual review and operator approval.
   - Approve the exact `script_clean.md` hash.
   - Writes `manual_agent_script_review.json`, `operator_script_approval.json`, and `script_lock.json`.

6. Script pace check.
   - New production narration targets 180-195 spoken words per minute.
   - Run after exact-hash script approval:
     `node bin/goldflow.mjs script pace-check --channel <channel> --series <series> --week <stable-run-slug> --episode <episode> --target-wpm-min 180 --target-wpm-max 195`
   - Writes `script_pace_report.json` for the approved script hash with word count and estimated runtime at the 187.5 WPM midpoint.
   - Deterministic script pace checks must not contain built-in story-family, episode-specific, or premise-specific hook phrases. Hook milestone timing is allowed only from an explicit operator/run-supplied `--hook-milestones` config; otherwise script pace records that hook milestones are not configured and must not block on inferred story content.
   - If explicit hook milestones are supplied, late milestones are recorded as `diagnostic_hook_status: missed_goal`. They never block, rewrite, or regenerate an approved script. Actual upload retention, not a deterministic timestamp rail, decides whether the editorial choice worked.
   - This is the script-stage budget plus optional configured hook gate; actual spoken WPM measurement happens after narration stitch and local Whisper timing.

7. Targeted speakability.
   - Preferred over broad speakability for polished scripts.
   - Requires the approved/locked script hash.
   - Writes `script_speakability_report.json`, `tts_spoken_overrides.json`, and `script_speakability_problem_areas_report.json`.
   - Use for TTS-only risks: protected terms, ranks, UI text, numbers, currencies, pronunciations, and known problem phrases.
   - It must not mutate `script_clean.md`.

8. Semantic continuity plan.
   - Extract overlapping script chunks through the identity-locked Codex Medium structured pool, starting at eight proven slots and success-ramping in-stage to twelve, validate each packet before accepting it, then run one Codex global reconciliation pass. Antigravity production capacity is zero for new identities. Legacy identities retain their recorded concurrency and routes. A malformed packet is preserved as exact recovery scope; accepted packets remain content-addressed and reusable.
   - Write `story_fact_ledger.json` with canonical entities, locations, props, UI motifs, and state transitions. Every fact requires a verbatim script excerpt and confidence; each transition also names the exact `transition_evidence_excerpt` where its `to_state` first becomes true. Unsupported or temporally ambiguous facts block rather than being deterministically repaired.
   - Extracts semantic scenes from locked script and bibles.
   - This is story/visual meaning, not word timing.

9. Voice plan.
   - Narrator-only by default.
   - Local Qwen3-TTS 1.7B Base conditioned by the exact pinned owned Joel reference is the default production identity. The quality lane itself is provider-neutral: Fish Audio, ElevenLabs, and generic engines are allowed only when preflight explicitly locks provider, model/revision, voice ID/hash, continuity contract, reference/calibration evidence, a null fallback, and a passed challenger-promotion receipt that exactly matches that identity. There is never automatic provider failover, and incomplete or tied bakeoff evidence retains Qwen.
   - Standalone bracketed system/UI dialogue remains spoken. Classify it as a `SYSTEM` source unit, send its contents without the outer brackets, and preserve the original bracketed line for captions. Only bracketed sound design, performance tags, pauses, and production directions are excluded from speech. Audit the locked script's system/UI count against `narration_generation_plan.json`; unexplained omissions block synthesis.
   - Build provider text only from approved story words. Legacy bracketed `performed_text` may inform `performance_intent`, but it must never enter `spoken_text` or the provider text payload. Every source component must close through exact text-bearing `goldflow_spoken_text_lineage_v1` receipts before grouping; a later punctuation-only direction chain must close on the exact provider request.
   - Character voice casting requires an explicit operator request.
   - Voice plan requires current speakability artifacts unless running a diagnostic bypass.
   - Current production writes `narration_text_ir.json`, `narration_generation_plan.json`, `audio_performance_plan.json`, `voice_direction_strategy_<episode>.json`, and `voice_reference_completeness_report.json`. The IR keeps immutable source text, caption text, and provider-safe spoken text separate, with an exact before/after hash receipt for every permitted transformation. Broad bracket deletion and unrecorded lexical edits are forbidden.
   - Preflight hash-binds `config/narration_delivery_reference_bank.json`. The bank declares neutral-forward, urgent, intimate, cold-reveal, and restrained-grief delivery classes from the same owned narrator. Only explicitly active references may condition production; an unpromoted request is recorded and safely falls back to neutral-forward.
   - Units are sentence-complete, prefer 20-42 spoken words, have a 48-word soft maximum and 60-word hard maximum, and carry one semantic boundary class, provider-neutral performance intent, requested delivery ID, and actually selected reference ID/hash. Short dialogue, system/UI, emphasis, and hard-barrier units remain atomic. The direction author may change punctuation but not lexical tokens.
   - Each unit compiles through a capability adapter into a hash-bound `provider_request`. A provider must declare whether it supports instructions, style controls, speed, pauses, or only reference-conditioned text. Unsupported direction is preserved as an explicit capability finding instead of being silently discarded.
   - New Qwen identities still use deterministic length-matched cohorts of four: every non-final cohort has four real units, the final cohort may contain one to three, and dummy padding is forbidden. External providers record their own batching in provider receipts and do not inherit the Qwen batch contract.

10. TTS generation and stitch.
   - The complete provider contract, result schema, QA rules, repair policy, and measured proof are documented in `docs/workflows/narration_quality_v2.md`.
   - Before importing the Qwen helper or loading the resident model, write `narration_tts_pre_synthesis_gate_<episode>.json`. Command entry first atomically bootstraps the same v2 artifact with `model_load_performed: false` and `synthesis_invoked: false`, so even an early path, concurrency, or policy failure leaves hash-valid zero-spend evidence; `historical_synthesis_authorized` preserves whether any prior gate had already authorized spend. Full validation then hash-binds the current run identity, canonical plan and source artifacts, complete spoken-text lineage, unit order and limits, system/UI and pronunciation audit, exact provider requests, voice/model/reference identity, and the authorized synthesis unit IDs. Any finding blocks before model load and leaves the current flags false. Only after every check and recovery-evidence check passes may the command atomically transition those fields to true immediately before helper/runner execution; the Python runner independently verifies that exact authorized gate before importing MLX, resolving the snapshot, or loading the model.
   - The default `tts narrate` route uses local Qwen3-TTS 1.7B Base with the exact pinned owned Joel reference audio and transcript. New Qwen identities load one resident model and synthesize deterministic length-matched cohorts of four with `Model.batch_generate`; existing identities without the explicit batch-four lock remain valid on the serial-unit adapter. This is fixed batching, never a continuous longform request.
   - Local Qwen materializes the same provider-output manifest used by external models and then enters the shared `finalize-provider` implementation. Its actual batch/cohort execution identity is retained separately from the request identity, so the common delivery/stitch/mastering path does not erase Qwen provenance.
   - An external provider returns one immutable WAV result per planned unit. Import it with `goldflow tts import-provider --episode-dir <episode-dir> --results <provider-results.json>`, then run `goldflow tts finalize-provider --episode-dir <episode-dir>`. Import rejects missing, duplicate, or reordered IDs; model/voice/continuity drift; request or synthesis-identity mismatch; stale audio hashes; nonpositive duration; and token-limit output.
   - An established serial Qwen/Liam identity is promoted only through an operator-approved `run relock-tts` recovery carrying `--promote-batch4 true`; the relock records the old and new synthesis contracts and invalidates from `voice_plan`.
   - The voice plan, jobs manifest, every unit synthesis identity/cache sidecar, and runner report bind the batch contract, complete cohort membership and order, nominal/effective size, cohort hash, and batch seed. The runner reports results in original narration order before waveform QA, ASR, WeSpeaker identity QA, selection, or stitching.
   - Qwen3 1.7B Base ICL does not honor per-unit `instruct` or native-speed control. Delivery comes only from the exact unit text, punctuation, and pinned owned Joel reference audio/transcript; runtime provenance reports `base_icl_reference_audio_only` and records that no speed was applied.
   - Completed units are content-addressed and reused only when the exact model/revision/runtime/text/Liam-reference identity, complete cohort identity, sidecar, QA decision, and WAV hash match. An exact-unit recovery hydrates every unaffected accepted unit from those immutable artifacts before synthesis and authorizes only the listener-confirmed repair IDs. It must never perform an initial full narration pass before the scoped repair. An interrupted initial invocation authorizes and submits only never-accepted unit IDs through a hash-bound serial incomplete-unit resume; accepted IDs never enter the runner job manifest again. Every preserved WAV and sidecar is checked before model import/load and again before the runner publishes its report. A fully passed invocation refuses an unscoped rerun. If a required preserved artifact is absent or stale, or raw runner output exists without the final report and QA that can prove acceptance, stop for triage rather than overwrite or regenerate it.
   - Shared provider finalization checkpoints unit QA, calibrated continuity, semantic stitch, mastering, full-stream delivery, and encode by exact content key. Embedded provider-unit Small-ASR may bypass a duplicate recognition pass only when its verified WAV hash, complete QA payload hash, current quality-contract hash, reuse policy, exact faster-whisper model/device/compute/options contract, recognized text hash, and ordered word-timing hash all match. Any mismatch takes the existing fresh-ASR path; an exact repaired unit invalidates only its dependent checkpoint scope.
   - Reaching an effective generation-token limit is objective truncation, never acceptable output. It receives no accepted cache sidecar and may recover only as that exact unit.
   - Every unit receives waveform QA, transcript comparison, and calibrated voice-continuity evidence. Delivery uses `small.en` screening and exact `medium` confirmation when required by the locked contract. The final stream runs one canonical Small pass that is promoted as the official timing candidate; Medium is localized to hash-bound suspect/boundary windows while preserving complete opening and final coverage. Confirmed opening/final loss, repeated or missing spans, insertion/deletion runs, wrong order/count, or WER above 0.05 blocks finalization; ambiguous substitution-only disagreements become hash-bound exact-listen items rather than automatic retries.
   - Every unit gets one creative synthesis submission. A missing, unreadable, empty, corrupt, token-limited, identity-drifted, or failed result stops with exact repair scope. A later repair may address only the exact unit or exact boundary and must bind the original plan, request, synthesis identity, audio, trigger, and listen-evidence hashes. Captions remain unchanged by a pronunciation-only spoken-text repair.
   - Unit edges are edited only from speech alignment. Preserve at least 80 ms before the first aligned word and 140 ms after the last; never trim from amplitude alone and never fade over aligned speech. Missing alignment preserves the entire unit. Four-millisecond fades are allowed only inside verified retained silence.

It applies directed anchors through a cubic per-frame perspective transform at 1080p/60 fps, eliminating integer `zoompan` micro-jitter without heavy 4K oversampling. `smooth_fast_ken_burns` remains an explicit faster integer-sampling fallback; `fill_ken_burns` is legacy/diagnostic. Render refuses a v2 profile that differs from the locked `run_identity.render_profile` without an explicit diagnostic bypass.

Static-share, first-minute contrast, repeated patterns, keyframe velocity, and movement-streak findings are advisory; deterministic code does not rewrite authored cuts to satisfy an aesthetic quota. Approved parallax uses visibly separated foreground/background scale while obeying the `foreground_cover` contract: both layers share keyframe anchors/timing/easing and foreground scale stays at or above background scale. Never translate a cutout laterally over an incompletely reconstructed plate; a declined or absent candidate keeps its single-plane move or static hold.
   - Render timing is absolute. Preserve the `start_sec` timeline from `section_image_prompts_hardened.json` / `visual_beat_plan.json`; do not globally scale image durations to fill the audio. If the visual plan has a gap before the next cut, hold the current image until the next cut's real start time or add new visual beats/images in a planning pass.
   - Each generated motion clip must be duration-probed immediately. Abort on malformed clips rather than continuing a long render.
   - Motion clips are cached by image hash, exact timing, motion-profile/filter hash, dimensions, fps, and encode settings. A changed cut regenerates one clip; unchanged clips are reused and recorded in `cut_execution_ledger.json`.

Record the selected binaries in the render report. With libass, burn ASS subtitles directly and skip the PNG/qtrle subtitle-overlay movie.

Aggressive motion should not mean constant random movement, but a premium render must not be all push-ins under different profile labels. Check `render_motion.motion_behaviors` for real variation before calling the MP4 review-ready.
   - Transitions should be hand-picked by beat, not default fade-to-black. Use smooth FFmpeg transitions such as wipes, pushes, slides, flashes, and manga-panel swipes where they match the moment, while preserving absolute cut timing.

The LLM audio planner should not author generic edit-transition whooshes/pops/snaps as narrative SFX.

For opt-in transition SFX, render/edit adds selected sounds at cut boundaries on top of the continuous mix; do not `acrossfade` the final audio between clips.
   - Render strips transition SFX when the audio bed report disables audio design. A separately named operator-approved proof/variant may use `--allow-transition-sfx-on-narrator-only true`; the render report records that override, and the official narrator-only artifact remains unchanged.

Visible cut changes every 2-4 seconds in the first 30 seconds and every 4-7 seconds from 30-180 seconds are advisory targets only. Record misses for editorial learning; never fail, retry, or regenerate an otherwise valid plan because of timing density.
   - Subtitles should be yellow text with small black outline and no box/background. Phrase-aware grouping may merge accidental one-to-four-word incomplete fragments when the result stays at most about twelve words and 3.4 seconds, while preserving deliberate short emphasis such as "No!" or "Two fingers rose." It never changes approved script words or Whisper timing anchors.
   - Subtitle text should come from the final approved/stitch script; Whisper provides timing anchors only.
   - Use the hardened prompt artifact so render image lookup matches approved scene prompts.
   - Final MP4s must be upload-safe `yuv420p`; verify format, duration, fps, audio codec, and size after render.
   - Audit rendered cut times against transcript/visual-beat `start_sec`. A final MP4 with the right total duration is not enough if individual images drift from the story.
   - Extract QA frames and spot-check final prompt/image/ref consistency before treating the render as publishable.

## Current Model And Provider Choices

- Narration TTS: local Qwen3-TTS 1.7B Base with the exact pinned owned Joel clone is the default; Fish Audio, ElevenLabs, and generic engines may use the same V2 lane only through an explicit model/revision/voice/continuity lock and immutable provider-output import. Sentence-complete units prefer 20-42 words, soften at 48, and hard-stop at 60. Source, caption, and spoken text remain separate and every text transformation is receipted. Provider capability adapters compile punctuation/performance intent without silently inventing support. Speech-aligned edge preservation, semantic joins, unit and full-stream dual-ASR delivery checks, calibrated owned-reference voice continuity, exact sample accounting, hash-bound listen/repair scope, and two-pass -16 LUFS/-1.5 dBTP mastering are required. Continuous longform requests, amplitude-only trim, fades over speech, tempo processing, token-limit output, automatic creative retries, and silent provider failover are forbidden.
- Voice route: narrator-only unless the operator explicitly requests character voice casting.
- Timing: local Whisper word timing on the final stitched narration.
- SFX assets: ModelsLab `/api/v7/voice/sound-generation` may generate or reuse locked assets after an identity-locked ChatGPT Web/Codex/local-Qwen or explicitly agent-authored plan.
- SFX prompting: concrete source/material/action/space prompts, short clean effects, no story-summary prompts, no melody, no speech, no crowd dialogue.
- SFX bank maintenance: run `goldflow sfx-bank rebuild` after importing or generating legacy bank assets, then `goldflow sfx-bank audit`. Use `goldflow sfx-bank list --status needs_review --query <term>` for spot-listen batches. Reject bad sounds with `goldflow sfx-bank reject --cue <cue_id> [--asset <asset_id>]`; promote a known-good alternate with `goldflow sfx-bank prefer --cue <cue_id> --asset <asset_id>`. Reuse only explicitly `available` bank assets, and prefer proven edit SFX instead of regenerating common whoosh-pop, manga snap, system ping, crowd gasp, room hush, screen-scan zip, camera flash pop, and low sub impact cues.
- Ambience assets: generated with the SFX model as loopable nonmusical beds. Plans should mark them with `recurrence_class: "ambience"`, `loop: true`, short `asset_duration_sec`, longer timeline `duration_sec`, and low gain around -34 to -28 dB.
- Score beds: local ACE-Step 1.5 is preferred when intentionally using chapter score beds. Current default model pair is DiT `acestep-v15-turbo` and LM `acestep-5Hz-lm-1.7B`. ModelsLab music generation is not the preferred production score path.
- Manhwa-only direction: Score drops: preferred scoring mode for narration-led recaps when music should be sparse. Use twenty to thirty-five short ACE-Step riser/hit accents for normal runs; for loud retention/final-review runs, use chunked score planning around sixty to eighty held ACE-Step drops, timed from Whisper, on focal drama, hype, reveal, reversal, payoff, escape, and cliffhanger beats.
- Score bank status: ACE-Step drops are currently generated per episode under `assets/audio/ace_step_score_drops`; they are not automatically a curated reusable score bank. Promote reusable score-drop prompts/assets only after spot-listen and explicit approval.
- Score bank maintenance: run `goldflow score-bank rebuild` to index episode-local ACE-Step drops, then `goldflow score-bank audit`. Use `goldflow score-bank list --status needs_review --query <tag>` for review batches; promote with `goldflow score-bank approve --id <bank_id>` and reject with `goldflow score-bank reject --id <bank_id> --note <reason>`. Keep this bank for reusable score-drop presets only; do not replace current-story score planning with random old drops.
- Image route: new `fast_premium_v1` identities default to the federated web-image pool. Gemini generates the style barrier, then five Flow plus three Gemini slots remain topped off. ChatGPT Image is operator-approved exact-ID fallback only. ModelsLab Flux Klein remains an explicit override. Each asset records actual provider/model and receives one submission with no automatic failover.
- Generated motion: Google Flow video is the new selective primary through provider-neutral artifacts and commands. Existing LTX 2.3 identities remain valid through a compatibility adapter.
- Explicit Codex/OpenAI imagegen runs: before any batch, run a one-image probe and verify that a real raster was imported into `assets/images` or `assets/images/references`. A nested Codex response that returns text/JSON success without a new raster is a failed provider probe; stop or use an approved fallback before spending image budget. If direct built-in Codex/OpenAI image generation is used manually, import each selected real raster with `goldflow imagegen import-codex`; partial reports with `missing_image_count > 0` are proof batches only and are not full-render image reports.
- Codex/OpenAI manual or subagent cuts must be generated into isolated one-cut staging folders. Do not actively generate into shared wave folders or copy the newest/global Codex cache raster; every worker stages exactly one PNG named for its assigned image ID and reports SHA-256. Import gates must reject duplicate hashes across distinct accepted image IDs. Repairs use fresh isolated folders and must not reuse stale staged or cached rasters.
- Before render, audit accepted image hashes from `imagegen_report_<episode>.json`. Any duplicate hash across distinct image IDs blocks render until the wrong/stale cut is regenerated, imported, and the duplicate audit passes.
- Visual prompts: normal production prose, current-scene-only, one prompt per visual beat, no standalone provider-exclusion payloads, with explicit reference slot mapping.
- Render audio: one continuous longform mix. Default is narrator-only; SFX, ambience, score, and transition SFX are opt-in variants.
- Render loudness: narration raised at longform mix with `--narration-volume-db 2` as the production starting point.
- Render subtitles: final approved/stitch script text timed by Whisper, not Whisper recognition text.

## Next Production Run Checklist

Use this checklist before spending generation time:

1. Source script
   - Start from polished spoken narration prose.
   - Remove production labels, narrator self-reference, bracketed notes, and screenplay metadata before ingest.
   - Ingest, manually review `script_clean.md`, then approve the exact hash.

2. Speakability
   - Run targeted speakability only by default.
   - Fix known TTS hazards before full TTS: dangling ellipses, clipped sentence endings, dense UI text, ranks, currencies, initialisms, and number pronunciation. Approved initialisms are expanded only in `tts_spoken_text` (`CEO` -> `C E O`); source prose and captions retain their original spelling, ordinary all-caps interface words are not expanded generically, and the versioned compiler distinguishes the `IT` initialism from the pronoun `it`.
   - Do not let speakability rewrite the story broadly unless explicitly requested.

3. Audio spine
   - Generate narrator-only Qwen3-TTS 1.7B Base narration with the exact owned Joel reference clone through `tts narrate`.
   - Confirm that the plan contains sentence-complete 20-42-word preferred units, uses 48 words as a soft ceiling and 60 as the hard ceiling, binds deterministic length-matched Qwen cohorts of four, restores source order before QA/stitch, uses no continuous longform request, rejects token-limit-hit output, and records the semantic boundary class for every join.
   - Review the opening/final units, every explicitly repaired exact unit, every protected-term/system/UI unit, and all acoustic or ASR warnings before committing downstream.
   - Run local Whisper timing after final stitched audio.
   - If any TTS unit is regenerated or the stitch changes, rerun Whisper and all timing-dependent stages. Do not tempo-normalize current Qwen/Liam production narration.

4. SFX and scoring
   - Narrator-only remains the default. Enable optional layers only for the locked audio intent; documentary scoring follows the Asset Afterlife profile, not the manhwa cue quotas or retention-mix recipes below.
   - Run SFX/score planning only after Whisper timing.
   - Manhwa-only direction: For narration-led humiliation/system stories, test SFX-only first: narrator plus system pings, phone buzzes, paper/object sounds, room hushes, laugh ripples, applause turns, and wealth-reveal impacts.
   - SFX prompts must name the source, material, action, space, and intensity. Example: `short cold crystalline digital transaction chime, quick attack, clean decay, subtle corporate interface texture`.
   - Use local ACE-Step for score drops or any intentional score beds:
     `ANIFACTORY_SCORE_PROVIDER=local_ace_step`.
   - Manhwa-only direction: Default for this style should be drops-only scoring; for final retention passes, prefer chunked score planning around 60-80 drops:
     `audio score-drops-chunked --score-target-drops 72 --score-drop-min-duration-sec 8 --score-drop-max-duration-sec 18 --chunk-sec 360 --concurrency 3`.
   - Manhwa-only direction: Keep SFX audible but controlled. Current narrator-forward retention mix starting point:
     `--narration-volume-db 3 --score-drop-boost-db 3 --signature-sfx-boost-db 2 --incidental-sfx-boost-db 2 --ambience-sfx-boost-db -2 --target-lufs -13 --true-peak-db -1`.
   - Transition SFX is handled by `visual transitions` plus render, not by the audio enrichment planner or longform-bed default. Sparse render-layer SFX mixing uses `amix normalize=0` so adding more inactive inputs cannot pull narration down; the final encoded mix is measured and normalized with a two-pass loudnorm, then measured again during QA.
   - Check the final longform mix for clipping and intelligibility. Use `--narration-volume-db 3` only if the limiter/loudness check passes.
   - Do not generate production score beds with ModelsLab music unless explicitly requested.
   - Manhwa-only direction: Optional score-drop layer: add twenty to thirty-five short ACE-Step riser/hit accents on focal beats for ordinary runs; use 60-80 held ACE-Step drops for loud retention/final-review runs, mixed by ducking the base score bed if one exists.

5. Visuals
   - Run visual beats before prompt authoring.
   - Beat planning is transcript-first: exact local final-script excerpt plus Whisper timing first, then editorial cue detection and visual job assignment. Target duration is a pacing guard, not the source of the cuts.
   - Generate and manually inspect style, character, location, prop/UI, and action refs before scene imagegen.
   - Use reference-only generation first, then selectively regenerate failed refs with `--reference-ids`.
   - Character state refs are definitive for identity and wardrobe. They should describe visible state only: face, hair, body type, grooming, concrete clothing construction/condition, cleanliness, injury if script-supported, expression, and posture. Narrative/social/financial state belongs in scene staging unless the script explicitly makes it visible on the body or clothes.
   - LLM-authored scene prompts should use normal production prose. Provider-exclusion payload fields such as `negative_prompt`, `avoid_list`, `exclude_list`, embedded `Negative prompt:` sections, and provider exclusion flags such as `--no` are not part of production prompt prose. Creative visual decisions belong to LLM authoring/review. Deterministic production sanitation should only validate and sanitize approved refs, paths, max-count limits, forbidden refs, payload-format poison, and non-creative unsafe UI label phrasing.
   - Reference priority: visible characters, location, prop/UI, action/effects, style only when no concrete refs are available.
   - For multi-character scenes, spot check attached refs before bulk imagegen. Check for wrong character refs, stale visible-subject refs, duplicate MC, face/body fusion, prop-embedded faces, speech bubbles, UI covering faces, and location drift.
   - If Flux times out or a sample fails, resume missing or rejected `--cut-ids` only. Keep completed good cuts cached.
   - Start imagegen concurrency around 6-12 on a fresh production run; raise only after quality and queue stability are confirmed.
   - Babysit the next run through staged visual gates before trusting full automation: manually review references, review the sanitized prompt sample, generate and contact-sheet the first small image batches, then keep periodic contact-sheet spot checks through high-risk sections.

6. Render
   - Render from the continuous mixed audio track.
   - Use final-script subtitles timed to Whisper, not Whisper-recognized text.
   - Manhwa-only direction: Spot-check generated `narrative_overlays` for additive copy, mobile readability, correct speaker/tail targeting, useful reaction/RPG styling, and face/subtitle-safe placement. Generated spelling alone remains non-blocking. If `engagement_overlay_plan_<episode>.json` is present and passed, separately check that its audience prompts do not cover faces, subtitles, image-native narrative graphics, or key UI and feel native to the current story beat.
   - Subtitle style: yellow text, small black outline, no background box.
   - Script-faithful subtitle tokens remain unchanged when TTS uses a pronunciation expansion. Bind `0X` to the Whisper words “zero times” rather than assigning it proportionally to the following phrase.
   - Motion style: new runs lock `--motion smooth_subpixel_ken_burns`; use `smooth_fast_ken_burns` only as an explicitly preflighted faster integer-sampling fallback. Both consume the same directed motion plan at 60 fps, while subpixel uses cubic fractional movement without heavy oversampling. Verify `render_motion.mode`, `render_motion.fps`, cache reuse counts, motion behavior variation, static/moving contrast, approved parallax count, and frame-cadence smoothness in the report. Use `fill_ken_burns` only as a deliberate legacy/diagnostic comparison.
   - Preserve absolute visual cut `start_sec`; do not globally scale cut durations. Probe motion clip durations and audit rendered image timing against transcript/visual beats.
   - Verify final MP4 codec/pixel format with `ffprobe`, especially `yuv420p` for upload compatibility.

7. Upload packaging
   - Supported manhwa or unchanged historical routes only. New workflow-locked non-manhwa runs stop at the unsupported-packaging gate pending their profile-specific adapter.
   - Use current own-channel and niche outlier evidence rather than a generic recipe.
   - Manhwa-only direction: Make the title explain both betrayal and revenge. Make the thumbnail one scene with one to three subjects, one clear arrow, one to four main words, at most two short labels, and no collage.
   - Approve the package, prepare the hash-bound manifest, upload privately first through the browser skill, and record upload and pinned-comment receipts.

## Change Policy

When a better tactic is discovered:

1. Document it here or in the relevant prompt/workflow doc.
2. Keep the pipeline philosophy intact: LLM authors, agent/operator reviews, code validates.
3. Prefer prompt/workflow improvements before deterministic creative repair. Production default is LLM authorship plus deterministic sanitation, not deterministic creative repair.
4. Commit small, revertable changes.
